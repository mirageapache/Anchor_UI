# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

`@anchor-ui/core` — a framework-agnostic Web Component library built with Lit 3 + TypeScript, styled by SCSS design tokens exposed as CSS custom properties. Published as ESM-only. Elements use the `aui-` prefix (`<aui-button>`, `<aui-tooltip>`, …). Docs/specs live in `doc/` (written in Traditional Chinese): `anchor-ui-spec.md`, `design-system.md` (token dictionary), `anchor-ui-components-list.md` (20 planned components), `anchor-ui-development-schedule.md` (phases / TASK-xxx ids referenced in commit messages).

## Commands

Package manager is pnpm, pinned by `packageManager` in `package.json` (the single source for CI and the Docker script; workspace includes `examples/*`); Node version in `.nvmrc`. `playwright` is pinned to an exact version and must match the `mcr.microsoft.com/playwright:v<version>-noble` image in `ci.yml` — `pnpm check:versions` (run in the CI lint job) fails on drift.

- `pnpm storybook` — Storybook on :6006 (primary dev/preview surface); `pnpm dev` — plain Vite server
- `pnpm build` — `tsc && vite build && pnpm build:tokens` → `dist/` (`index.js`, `.d.ts`, `styles.css`, `tokens.css`)
- `pnpm verify:package` / `pnpm size` — run after build (CI does both in the build job): tree-shaking / `exports` / `sideEffects` / published-files checks, and size-limit budgets per entry (`.size-limit.mjs`: gzip, `lit` ignored, limit = baseline + 10%)
- `pnpm typecheck`, `pnpm lint`, `pnpm stylelint`, `pnpm format:check` (these four are what CI runs before build; `:fix` / `format` variants exist)
- `pnpm test` — web-test-runner (Playwright Chromium) over `src/components/**/*.test.ts`, `src/internal/**/*.test.ts` and `src/*.test.ts` (e.g. `theme.test.ts`), excluding `*.visual.test.ts`
  - single file: `pnpm test --files src/components/button/button.test.ts` (or `pnpm wtr "<glob>"`)
  - `pnpm test:watch`, `pnpm test:coverage` (thresholds: 85% statements/functions/lines, 75% branches)
  - `pnpm test:a11y` — only `*.a11y.test.ts` (axe-core via `@open-wc/testing`'s `to.be.accessible()`)
  - `pnpm test:visual:docker` / `pnpm test:visual:docker:update` — visual regression (`*.visual.test.ts`, excluded from `pnpm test`) inside the official Playwright Docker image; baselines live in `screenshots/Chromium/baseline/` and must only be generated there (the visual config refuses to run outside Linux). Requires Docker. Shared setup (fonts via `@fontsource`, tokens, animation freezing) is `src/test-utils/visual.ts`; a new component should get a `<name>.visual.test.ts` declared with `describeVisual(title, cases)` (each case is shot in both themes). The `:update` run then calls `scripts/visual-baseline-diff.mjs`, which lists changed baselines and writes before/after/diff images to `screenshots/Chromium/changes/` (CI does the same on PRs against the target branch). Note the directory really is `Chromium` (capital C) — paths are case-sensitive on Linux/CI.
- `pnpm test:vue` / `pnpm test:angular` — integration tests in `examples/vue3` and `examples/angular` (vitest + happy-dom) that consume the library via `workspace:*`

Releases follow `doc/anchor-ui-release-guide.md`: `package.json` `version` is the last released milestone and only changes in a release PR from `main` (`release/v<version>`, version bump only); after merging, an annotated `v<version>` tag on the merge commit triggers `.github/workflows/release.yml` (checks the tag is on `main`, waits for that commit's required checks — read from the `main` Ruleset by `scripts/wait-for-ci.mjs` — to pass, runs `pnpm release:pack` incl. `scripts/verify-release.mjs` tag/version check, creates a GitHub Release with the tarball, prerelease when the version contains `-`); then merge `main` back into `develop`.

Commits are enforced by commitlint (Conventional Commits; types: feat, fix, docs, style, refactor, perf, test, build, ci, chore, revert) and Husky + lint-staged on pre-commit.

## Architecture

**Component layout** — each component is a folder `src/components/<name>/` with `<name>.ts` (LitElement class), `<name>.styles.ts` (`css` tagged template), `<name>.types.ts`, `index.ts` (re-exports class + types), `<name>.test.ts`, `<name>.a11y.test.ts`. A new component must also be exported from `src/components/index.ts` (which `src/index.ts` re-exports), get its `package.json` `exports` / `sideEffects` entries regenerated with `pnpm sync:package` (from `scripts/components.mjs`, the single source of the component list; the defining module must be named `<name>.ts`), a size baseline in `.size-limit.mjs` `BASELINES`, and gets a story in `src/stories/`. If it imports another component (e.g. icon-button → tooltip), add that edge to `ALLOWED_COMPONENT_DEPS` in `scripts/verify-package.mjs` — the tree-shaking check uses this explicit allow-list (not the source imports) and also inspects bundled modules, so undeclared cross-component code fails. `pnpm verify:package` and `pnpm size` fail if any of these are missing. Vite picks up the build entry automatically. Keep `"./src/**/*.ts"` in `sideEffects`: the field also applies to the library's own build, and without it bare registration imports such as `import '../tooltip/index.js'` get tree-shaken out of `dist/`.

**Tokens** — `src/tokens/*.scss` is the single source of truth (colors, typography, spacing, radius, motion). It is compiled two ways: into `dist/tokens.css` via `build:tokens` (sass), and also exposed as source SCSS through package exports (`./tokens`, `./reset`). Component styles reference tokens via `var(--space-lg, 24px)` with literal fallbacks; they never hardcode theme values.

**Theming** — dark mode is driven by `data-theme="dark"` on `<html>`. `setTheme` / `getTheme` / `toggleTheme` in `src/index.ts` manage it and briefly add a `.theme-transitioning` class for smooth transitions.

**Build** — Vite library mode, ESM-only with `preserveModules` (output mirrors `src/`): a full entry `src/index.ts` (registers every component) plus one entry per `src/components/*/index.ts`, exposed as `@anchor-ui/core/<name>` for tree-shakable on-demand imports. `lit*` and `@floating-ui/*` are externalized (`@floating-ui/dom` is a runtime dependency); test, story and `test-utils` files are excluded from the `.d.ts` output. `__PKG_VERSION__` is injected from `package.json` via Vite `define` (declared in `src/env.d.ts`). `@` aliases `src/`.

**Tooltip** is the most involved component: native Popover API (top layer) + `@floating-ui/dom` (`computePosition`/`autoUpdate`/flip/shift/arrow), emits cancelable `aui-show`/`aui-hide` and `aui-after-show`/`aui-after-hide` events. Custom events are prefixed `aui-`.

**Form controls** — `<aui-input>` and `<aui-segmented>` are form-associated custom elements sharing `src/internal/form-control.ts` (`FormControlController`: `attachInternals`, synchronous `setFormValue`, and the hidden-input + `reset`-listener fallback when `attachInternals` is missing, e.g. happy-dom). For `<aui-input>`: `setFormValue` runs synchronously on every value change, validity is mirrored from the inner native `<input>`/`<textarea>` (the single source of truth, incl. `setCustomValidity`) into `ElementInternals`, and it implements `formResetCallback` / `formDisabledCallback` / `formStateRestoreCallback`. `value` follows native dirty-value semantics (the `value` attribute is `defaultValue`). `src/internal/form-owner.ts` resolves the form owner in the fallback (shared with Button). `<aui-segmented>` renders `options` as a WAI-ARIA radiogroup with roving tabindex inside its shadow root and only submits when the value matches an option. The native `input` event is composed and crosses the shadow boundary as-is; `change` is not, so it is re-dispatched on the host — in both cases `value` is already updated. `<aui-field>` pushes its `label`/`description` into the slotted `<aui-input>`, `<aui-output>` or `<aui-segmented>`, which wire them up inside their own shadow roots (IDREFs can't cross shadow roots); verify such relations with `getAxNode` from `src/test-utils/ax.ts`. A component only registers the components it renders itself (field → icon-button), not the ones users slot into it.

**Shared internals** — `src/internal/` holds non-exported helpers shared across components: `spinner`, `inactive-click`, `form-owner`, `form-control`, and the overlay foundation for Modal/Alert/Toast/Drawer — `scroll-lock` (nested ref-count + scrollbar compensation), `focus-return` (deep `activeElement` through shadow roots), `top-layer` (`raisePopover`, a modal layer stack, and `followTopModal` which moves overlays such as the Toast viewport into the topmost modal's subtree, because a modal `<dialog>` makes everything outside it inert even when it is visually above). Page-global state lives on `globalThis` via `sharedState()` so multiple library copies agree. Call `pushModalLayer()` only after `dialog.showModal()` (and pop after `close()`); `followTopModal` records the element's home when it first moves into a modal and falls back to `<body>` if that home is gone; `raisePopover` re-raises open nested popovers too. Tests sit next to them (`src/internal/*.test.ts`).

**Tests** — run in real Chromium via web-test-runner with esbuild TS transform (Playwright's default `--hide-scrollbars` is disabled so scrollbar-dependent behaviour can be tested). A11y tests load `/dist/tokens.css` in a `<link>` so contrast checks use real tokens — **run `pnpm build` first** or color-contrast results will be wrong/missing.

**Examples** — `examples/vue3` and `examples/angular` verify the custom elements work inside host frameworks (property/event binding, and two-way form binding: Vue `v-model` works as-is, Angular needs `ngDefaultControl` on `[(ngModel)]` / `[formControl]`); they depend on the built `dist/`. They run on happy-dom, which has two gaps: it does not retarget events from shadow roots to the host (so IME-composition and `blur` behaviour that frameworks read from `event.target` is covered by the Chromium "framework binding contract" tests in `src/components/input/input.test.ts` instead), and zone.js cannot wrap its `MutationObserver` (its methods are non-enumerable), which `examples/angular/src/test-setup-happy-dom.ts` fixes before zone.js loads. Simulate typing by setting the inner `.control` value and dispatching a composed `input` event. Each example also has `tests/entries.spec.ts`, which imports only per-component entries (`@anchor-ui/core/field`, `/input`) and asserts which tags end up registered; it relies on Vitest's per-file isolation (a fresh environment and `customElements` registry per test file), so keep that isolation enabled.

## Conventions

- JSDoc on component classes uses the custom-elements-manifest tags (`@element`, `@slot`, `@csspart`, `@fires`); keep them updated when changing a component's API.
- Source comments and docs are mostly in Traditional Chinese; match the surrounding language.
- Font files are intentionally not bundled — only font-family tokens are defined (see README "字體載入").
